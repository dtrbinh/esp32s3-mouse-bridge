# BLE-Only Status LED Design

## Intent

Add low-brightness visual feedback to the one-board `apps/ble_only` firmware
using the Waveshare ESP32-S3-Zero onboard WS2812 LED on GPIO21. The LED shows
whether BLE is scanning or connected, whether profile modifications are
enabled, and which of the 14 profiles is selected without requiring UART logs.

This feature applies only to `apps/ble_only`. It must not claim GPIO21 or add an
LED task to the matched two-board `apps/input` and `apps/output` applications.

## State priority and timing

The displayed state is selected in this order:

1. BLE not connected, including startup, scan, reconnect, and bond clearing:
   yellow blinking with a 300 ms full cycle (150 ms on, 150 ms off).
2. BLE connected and mods disabled: green blinking with a 2,000 ms full cycle
   (1,000 ms on, 1,000 ms off).
3. BLE connected and mods enabled: the selected profile color, continuously on.

Changing profile updates the solid color on the next LED task sample. Toggling
mods off immediately exposes the connected green blink; toggling mods on
restores the selected profile color. Starting a bond clear marks BLE
disconnected before the asynchronous close completes, so yellow scan feedback
does not wait for the close event. A physical BLE disconnect has the same yellow
scan state.

The LED task samples state every 50 ms, is statically allocated, and is pinned
to CPU0 with diagnostics and BLE control. It is lower priority than the BLE
worker and never runs in a BLE callback or the CPU1 report/HID fast path. The
RMT LED driver is initialized before BLE starts; the LED stays off until that
initialization succeeds.

## Profile palette

Palette entries are logical RGB values before the shared power limiter:

| Profile | Name | RGB |
|---:|---|---:|
| 1 | Red | `255, 0, 0` |
| 2 | Vermilion | `255, 48, 0` |
| 3 | Orange | `255, 112, 0` |
| 4 | Rose | `255, 32, 96` |
| 5 | Pink | `255, 64, 180` |
| 6 | Violet | `176, 32, 255` |
| 7 | Indigo | `80, 32, 255` |
| 8 | Blue | `0, 72, 255` |
| 9 | Sky | `0, 160, 255` |
| 10 | Cyan | `0, 255, 255` |
| 11 | Teal | `0, 255, 144` |
| 12 | Cool white | `176, 208, 255` |
| 13 | Warm white | `255, 176, 96` |
| 14 | Magenta | `255, 0, 144` |

Yellow `255, 192, 0` and green `0, 255, 0` are reserved for scan and connected
pass-through states, respectively. Profile colors avoid those exact system
colors even where adjacent hues are used.

## Brightness and thermal limit

Every nonzero logical RGB color passes through one shared 10% total-current
limiter. The emitted 8-bit channels preserve the logical color ratio and their
sum never exceeds 76, which is 10% of the full three-channel sum of 765. This
keeps white and mixed colors within the same total channel budget as state and
single-hue colors. Integer rounding must never raise the emitted sum above 76.
Off is exactly `0, 0, 0`.

The brightness rule is portable and host-tested independently of ESP-IDF and
the RMT driver.

## Runtime interfaces

`BleHogpClient` exposes a lock-free `connected()` snapshot backed by an atomic
boolean. It becomes true only after a HID device opens and its report maps are
valid. It becomes false on close and at the start of `clear_bond()`.

A portable LED status model consumes:

- BLE connected state;
- mods enabled state;
- selected profile number in the range 1-14;
- monotonic elapsed milliseconds.

It produces one final, already-limited RGB triplet. The ESP-IDF LED controller
owns the WS2812 handle, writes only when the RGB output changes, and logs driver
initialization failures. Failure to initialize the LED is non-fatal: BLE and
USB HID must continue operating normally without visual feedback.

## Dependency and configuration

`apps/ble_only` adds the managed component `espressif/led_strip` compatible
with the ESP-IDF 6.0.3 toolchain and uses its RMT backend without DMA for one
pixel. GPIO21 is configurable through `CONFIG_BLE_ONLY_LED_GPIO`, defaulting to
21. The dependency lock is regenerated by the firmware build.

## Verification

Host tests cover all three state priorities, both blink boundaries, all 14
profile mappings, profile-number clamping, off output, color-ratio scaling, and
the hard sum-of-channels limit of 76. Existing host tests remain green.

Firmware verification builds both `apps/ble_only` and the shared `apps/input`
BLE client, confirms every new application task is statically allocated and
pinned, and preserves CPU1 for the report/TinyUSB/HID fast path.

Hardware validation remains `CHƯA CHẠY` until checked on the user's board:
yellow fast scan, green 2-second connected pass-through blink, 14 solid profile
colors, immediate state changes from BOOT actions, and acceptable temperature
after at least 30 minutes.
